# 积分日志与提交记录

管理员入口：系统管理 → 运维与审计 → 积分日志。

统一展示子任务基础分和修改分、历史质量分、独立设计需求、素材采纳、PO、手动调整、异议更正、退单扣分。以基础流水和调整流水为准，PO专表是同一事件的业务记录，不再重复计入。可按人员账号或名称、入账日期、来源、关键词和正负方向筛选；账号与名称共用一个输入框，支持模糊查询和回车查询，汇总与当前筛选范围一致。积分日志和子任务核对使用相同的人员条件，分别保留各自的分页。

新子任务每次提交由服务器记录时间，并冻结本轮规则、应发分和修改请求编号。企划确认时记录确认人、确认时间，积分关联该提交版本；确认和入账在同一事务内，数据库唯一约束防止重复入账。无积分修改仍记录提交与确认，但不生成积分流水。独立设计需求保留最新成果提交时间，沿用其自身发分流程。

子任务核对按提交日期和人员范围检查漏账、错分、错人、错规则、无积分轮出现流水及确认前入账。其他来源可通过统一流水追溯，不在子任务自动核对范围内。历史缺少追踪字段时显示未记录，不反推、不重算、不自动补发。

已有积分或退单调账记录的项目、子任务禁止物理删除，避免账务历史消失。发现异常后应先核实业务和原始流水，使用管理员调账或既有异议流程更正，保留原流水和更正原因。

## 月度积分与跨月事项

设计师月度积分按每笔流水的 `accounting_month` 汇总，任务流水仅计入参与绩效的记录，调整流水计入相同归属月。新产生的子任务积分以本次交付确认时间归月，缺少确认时间时按入账当月归属；任务里程碑、提交时间和最终完成时间不移动已有积分。9 月确认 3 分、10 月确认 3 分的任务累计为 6 分，10 月只计 3 分。后续补扣分新增调整流水，保留原流水和归属依据。

管理员在设计师绩效中点击当期积分，可查看该人所选月份或年份的全部流水。关联事项同时列出当期完成事项和当期积分涉及的全部子任务、设计/送审需求，包含尚未完成、其他月份完成、负分和净额为零的事项；同一事项多笔流水合并为一行。每项只显示所选期间实际计入的积分，月度为“当月积分”，年度为“全年积分”，不显示累计或其他月份的分数；完成状态保留，原完成数量仍按完成时间统计。同号任务和需求按类型分别核算，改派任务的历史积分仍归原流水接收人。异议和退单按明确关联纳入事项；没有明确任务关联的手动调账、素材奖励等逐笔单列，不根据来源编号猜测任务。

“导出月度积分与关联事项”生成三张完整表：月度积分汇总、当月积分明细、当月关联事项。页面规则版本仅筛选屏幕列表，所有导出表始终包含全部来源和关联事项。第三表共12列，唯一的积分列为最后一列“当月积分”，不导出累计分和其他月份分数；页面总分、明细合计和关联事项当月分合计必须一致，否则拒绝导出。例如9月3分、10月3分的跨月任务，在10月关联事项中只显示3分。

现有有效归属月和原始分数保持不变，新报表直接读取历史流水，无须重新发分或迁移。可运行 `python3 scripts/audit-monthly-points.py` 只读整理本地积分；显式加 `--production-read-only` 才读取生产。审计输出逐人逐月汇总、原始明细和异常清单，缺月、非法月、重复候选或关联异常均需核实，脚本不更新数据库。归属月与确认/入账月不同只作提示，不自动改写历史月份。
