# EMIE CRUD 接口规范

## 目标

接口首先表达业务资源与权限边界，再表达页面需求。客户端只提交筛选条件和写入意图；身份、角色范围、审计主体均由服务端会话确定。

## 统一约定

| 场景 | 规范 |
| --- | --- |
| 集合读取 | `GET /api/{resources}`；支持 `page`、`size` 与明确筛选参数，禁止默认全量读取 |
| 分页响应 | `{ items, page, size, total, totalPages }` |
| 单项读取 | `GET /api/{resources}/{id}` |
| 创建 | `POST /api/{resources}`，服务端校验并记录审计 |
| 更新 | `PUT /api/{resources}/{id}`，只接受可编辑字段，服务端校验归属/状态 |
| 删除 | `DELETE /api/{resources}/{id}`，需业务权限与审计；有历史关联时优先状态化删除 |
| 参数错误 | HTTP 400，`{ code, message }` |
| 未登录/无权 | 分别为 HTTP 401 / 403；不得通过客户端传入 role 或 userId 绕过 |

## 列表查询 SOP

1. 明确资源、排序、权限范围和每页上限。
2. 将筛选参数标准化并在控制器层拒绝非法值。
3. 仓储层只拼接实际使用的谓词；禁止 `:param IS NULL OR ...` 作为通用条件。
4. 内容查询与总数查询必须使用同一权限和筛选谓词。
5. 只补与实际 SQL 顺序一致的组合索引；发布前以生产副本或 `EXPLAIN` 验证。
6. 保留旧接口一个兼容周期，调用方全部迁移后再单独移除。

## 当前落地状态

- 项目列表 `GET /api/projects/page` 已符合上述分页响应、服务端筛选、会话权限范围和参数校验规范。
- 旧 `GET /api/projects` 仅作为旧页面兼容接口，不得在新增列表或筛选功能中使用。
- 其余 CRUD 资源按风险分批迁移：先管理配置类资源，再项目子任务/评分等状态机资源；不得在无回归验证的情况下批量改变既有响应结构。
