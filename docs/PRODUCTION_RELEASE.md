# 生产发布稳定流程

生产发布采用候选容器 + 健康检查 + 原子切换：

1. 代码必须提交并推送到 `project_manager_system`，工作区保持干净。
2. 发布脚本自动执行 Java 21 构建和全部自动化测试。
3. 生产服务器先创建候选容器，旧容器保持在线。
4. 候选容器必须通过存活检查、数据库连接、Redis、首页和静态资源检查后才允许切换。
5. 切换前自动备份数据库和旧版本 JAR。
6. 切换期间如果新容器异常，脚本自动恢复旧容器。
7. 生产同时只允许一个发布；并发发布会被锁拒绝。
8. 发布脚本按约定自动递增版本：`1.0.8 → 1.0.9`、`1.0.9 → 1.1.0`、`1.9.9 → 1.10.0`；主版本不会自动进入 2.0.0，只有明确指定时才切换。版本注入候选容器并核对页面版本号，不再手写版本迁移。

业务兼容原则：数据库迁移先扩展后收缩，旧版本和新版本短时间并存时不能互相破坏；新功能必须保持旧接口可用，确认稳定后再删除旧结构。
