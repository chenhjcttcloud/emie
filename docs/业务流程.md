# EMIE 设计项目管理系统 — 业务流程文档

> 版本: 1.0 | 最后更新: 2026-06-28

---

## 一、系统概述

EMIE 设计项目管理系统（DesignPM）是一个面向 IP 联名产品设计团队的多角色协作平台，支持**渠道定制单**和**常规品设计**两种项目类型，涵盖从需求提交、设计执行到评分验收的全流程管理。

## 三、项目类型

### 3.1 渠道定制单（channel_custom）

**场景**：销售对接客户，提出定制化产品设计需求。

**特点**：
- 由**销售**创建项目
- 需由**产品企划**接单后启动
- 验收采用**双角色评分**（企划 50% + 销售 50%）
- 终止流程需**双方确认**

### 3.2 常规品设计（regular）

**场景**：产品企划主动发起公司常规产品设计。

**特点**：
- 由**产品企划**直接创建（跳过接单环节）
- 验收由**企划单一角色评分**（权重 100%）
- 可直接终止（单方操作）

## 四、完整业务流程

### 4.1 渠道定制单流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     渠道定制单 — 完整生命周期                            │
└─────────────────────────────────────────────────────────────────────────┘

  销售创建项目
     │
     ▼
  【草稿 / draft】            ← 销售填写需求后自动跳过此状态
     │
     ▼
  【待企划接单 / pending_planner】
     │  ← 企划手动接单 (plannerAccept)
     ▼
  【企划已接单 / planner_accepted】
     │  ← 企划添加子任务，指定设计师
     ▼
  【进行中 / in_progress】
     │
     ├──────────────────────────────────────────────────────┐
     │  子任务流转（详见 4.3）                                │
     │                                                       │
     │  待接单(pending) → 设计中(accepted) → 待验收(delivered)│
     │      ↓ 设计师接单        ↓ 设计师交付        ↓ 企划验收 │
     │                                                 ↓      │
     │   企划已通过 + 评分(planner_approved) → 销售确认评分     │
     │                                      → 已通过(approved) │
     │                                                       │
     │  ← 企划可驳回(交付不合格时) → 设计师重新交付            │
     └──────────────────────────────────────────────────────┘
     │
     ├── 所有子任务已通过(approved)且评分完成
     │   └──→ 【已完成 / completed】
     │
     ├── 所有子任务已通过但评分未完成
     │   └──→ 【待评分 / completed_pending_score】
     │
     ├── 暂停 / 恢复
     │   ├── → 【已暂停 / paused】→ 恢复 → 原状态
     │   └──  仅 pending_planner / planner_accepted / in_progress 可暂停
     │
     └── 终止（详见 4.5）
```

### 4.2 常规品设计流程

```
  企划创建项目（直接到 planner_accepted）
     │
     ▼
  【企划已接单 / planner_accepted】
     │  ← 企划添加子任务
     ▼
  【进行中 / in_progress】
     │
     │  子任务流转（同渠道单，但验收后评分单独提交）
     │  pending → accepted → delivered → approved
     │                                   └→ 后续企划单独评分
     │  ← 驳回 → rejected → 重新交付
     │
     ├──→ 【已完成 / completed】（所有子任务 approved + 评分完成）
     └──→ 可直接终止（单方操作）
```

### 4.3 子任务状态流转

```
                    ┌──────────────┐
                    │   待接单      │
                    │  (pending)   │
                    └──────┬───────┘
                           │ 设计师接单 (taskAccept)
                           ▼
                    ┌──────────────┐
                    │   设计中      │
                    │  (accepted)  │
                    └──────┬───────┘
                           │ 设计师交付 (taskDeliver)
                           ▼
                    ┌──────────────┐
                    │   待验收      │
                    │  (delivered) │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
       ┌──────────┐  ┌──────────┐  ┌──────────┐
       │ 企划驳回  │  │企划已通过│  │ 直接通过 │
       │(rejected) │  │(planner_ │  │(approved)│ ← 常规品
       │           │  │approved) │  └──────────┘
       └─────┬─────┘  └─────┬────┘       │
             │              │ 销售确认评分 │
             │              ▼             │
             │       ┌──────────┐         │
             │       │ 已通过    │         │
             └──────→│(approved)│←────────┘
                      └──────────┘
                          │
                          ▼ 评分完成后
                   ┌──────────────┐
                   │ 项目完成      │
                   │ (completed)  │
                   └──────────────┘
```

**状态说明**：

| 状态 | 标签 | 说明 | 操作者 |
|------|------|------|--------|
| `pending` | 待接单 | 设计师尚未接单 | — |
| `accepted` | 设计中 | 设计师已接单，正在执行 | 设计师 |
| `delivered` | 待验收 | 设计师已完成并提交成果 | 设计师 |
| `planner_approved` | 企划已通过 | 企划通过+评分，待销售确认（仅渠道单） | 企划 |
| `approved` | 已通过 | 最终验收通过 | 企划/销售 |
| `rejected` | 已驳回 | 成果不合格，退回重做 | 企划 |

### 4.4 评分体系

#### 评分维度

| 维度 | 范围 | 说明 |
|------|------|------|
| 审美 (aesthetics) | 1-10 | 设计美感评分 |
| 创新 (innovation) | 1-10 | 设计创新性评分 |

#### 评分规则

| 项目类型 | 评分角色 | 权重 | 说明 |
|----------|----------|------|------|
| 渠道定制单 | 企划 + 销售 | 各 50% | 企划先评分 → 销售确认评分 |
| 常规品 | 企划 | 100% | 只有企划评分 |

#### 评分流程

```
渠道定制单：
  企划验收通过时 → 自动创建企划评分记录（带分值）+ 销售评分记录（空）
                    ↓
  销售确认评分时 → 更新销售评分记录
                    ↓
  两者都有值 → 子任务评分完成

常规品：
  企划验收通过时 → 创建企划评分记录（空）
                    ↓
  企划单独提交评分 → 评分完成
```

#### 项目完结条件

1. 所有子任务状态 = `approved`
2. 每个子任务的评分记录中，所有角色的 `aesthetics` 和 `innovation` 字段均不为空
3. 满足以上条件 → 项目状态更新为 `completed`
4. 满足条件1但未满足2 → 项目状态 = `completed_pending_score`（待评分）

---

### 4.5 暂停与恢复

| 操作 | 说明 | 允许的状态 |
|------|------|-----------|
| **暂停** | 保存当前状态，项目暂停 | `pending_planner` / `planner_accepted` / `in_progress` |
| **恢复** | 恢复到暂停前状态 | `paused` |

**恢复逻辑**：
- 优先恢复到 `prePauseStatus` 保存的原状态
- 若原状态无效，降级判断：有活跃子任务 → `in_progress`，否则 → `planner_accepted`

### 4.6 终止流程

#### 渠道定制单终止

```
状态 = pending_planner（未接单）
  └──→ 直接终止 → terminated

状态 = 工作中（planner_accepted / in_progress / paused）
  └──→ 一方发起终止请求 → pending_terminate
        ├── 另一方确认 → terminated
        ├── 发起方取消 → 回到原状态 (in_progress)
        └── 发起方重复请求 → 提示"请等待对方确认"
```

#### 常规品终止

```
任何状态 → 直接终止 → terminated（单方操作，无需确认）
```

## 七、认证与安全

### 7.1 登录方式

支持三种方式登录：
- **用户ID**（如 `sales_sun`）
- **手机号**（11位）
- **邮箱地址**

### 7.2 注册流程

```
填写注册信息 → 图形验证码 → 邮箱验证码 → 校验唯一性 → 创建用户并自动登录
```

需要填写：用户ID、姓名、手机号、邮箱、密码、角色

### 7.3 安全机制

| 机制 | 说明 |
|------|------|
| IP 频率限制 | 登录/注册每分钟最多 30 次（内存滑动窗口） |
| XSS 防护 | 所有文本输入经过 sanitize，移除 HTML 标签和危险属性 |
| 文件上传校验 | 白名单扩展名、禁止路径穿越、UUID 重命名 |
| 密码存储 | SHA-256 哈希，非明文存储 |
| Token 认证 | 服务端生成 64 位随机 token，请求头 `X-Auth-Token` 传递 |
| 并发控制 | 企划接单锁定 Project 行；设计师接单同时锁定 Project 和 SubTask 行 |

## 八、日志与归档

### 8.1 操作日志

所有关键操作自动记录操作日志，包含：
- 操作内容（action）
- 操作人（username + role）
- 操作时间（time）
- 关联项目（project_id）

### 8.2 日志归档

- **定时任务**：每月 1 日凌晨自动执行
- **归档范围**：上个月的操作日志
- **归档方式**：导出为 gzip 压缩的 JSON 文件，保存到 `logs/` 目录
- **查询机制**：自动合并数据库记录 + 归档文件内容

## 十、项目状态总表

| 状态 | 标签 | 可操作 | 说明 |
|------|------|--------|------|
| `draft` | 草稿 | 企划接单 | 创建初始态（当前已跳过） |
| `pending_planner` | 待企划接单 | 企划接单、暂停、终止 | 渠道定制单创建后 |
| `planner_accepted` | 企划已接单 | 添加子任务、暂停、终止 | 企划已确认接单 |
| `in_progress` | 进行中 | 子任务操作、暂停、终止 | 已有子任务进入工作流 |
| `paused` | 已暂停 | 恢复、终止 | 暂停状态 |
| `pending_terminate` | 终止确认中 | 对方确认/发起方取消 | 渠道单双方确认 |
| `terminated` | 已终止 | —（终态） | 项目结束（非正常完结） |
| `completed_pending_score` | 待评分 | 提交评分 | 子任务已验收但评分未完成 |
| `completed` | 已完成 | —（终态） | 项目正常完结 |
