# 生产稳定性 SOP

## 目标

让故障可发现、影响可隔离、数据可恢复、发布可回滚。任何“稳定”结论都必须有指标、测试和回滚证据。

## 发布门禁

发布前必须满足：

1. 工作区无未确认改动，提交 SHA 与发布 SHA 一致。
2. Java 21 构建、全部自动化测试、前端语法检查通过。
3. 数据库备份成功且可读取，迁移脚本已审核。
4. 主/后台连接池配置、数据库最大连接数和文件目录空间已核对。
5. 项目、子任务、文件上传、飞书同步、通知重试关键链路回归通过。
6. 候选容器启动、健康检查、版本检查和双连接池检查通过。
7. 发布失败自动保留旧容器和备份，并执行回滚。

## 运行门禁

持续观察：

- 连接池 active、idle、waiting、timeout、leak；
- 接口 4xx/5xx、P95/P99、慢事务；
- JVM 堆、GC、线程和 OOM；
- 上传、缩略图、预览和存储空间；
- 飞书同步队列 pending/processing/fail 和最近失败；
- 通知 outbox、重试和死信数量。

## 资源生命周期规则

- 数据库连接只在短事务内使用，事务结束立即归还池；
- 数据库事务不得包住 HTTP、SFTP、压缩、图片处理或大文件读写；
- 文件流、压缩流、SFTP Session/Channel 使用自动关闭；
- 外部 HTTP 必须设置连接超时、请求超时和有限重试；
- 队列必须有幂等键、锁、退避、最大重试和死信；
- SSE、线程池和定时任务必须有超时、退避和关闭策略。

## 故障处理

先保护业务：停止重复重试和高耗时任务，保留现场日志和指标；再定位根因；修复必须先本地验证，生产只通过原子发布脚本执行。任何数据库或文件删除操作都必须先备份并提供回滚路径。

## 当前落地记录

已完成并在本地验证：

- 主连接池与后台连接池分离，后台同步、通知重试和队列 Repository 使用后台池；事务结束后连接由 Spring/Hikari 自动归还，不手动关闭 JPA 连接。
- 项目详情、分享访问、归档恢复、通知重试等链路缩短事务范围，禁止事务包住 SFTP、压缩、HTTP 和大文件处理。
- 文件流、导入流、压缩流和 SFTP 资源使用自动关闭；上传并发设置上限，避免大文件请求耗尽工作线程和连接池。
- 项目日志查询限制为最近 200 条，避免替换 `orphanRemoval` 集合导致 500 和堆内存压力。
- SSE 服务端超时延长，客户端采用退避重连；前端版本检查保持低中断升级，不强制断开现有用户连接。
- 增加全局异常响应、数据库异常降级、外部 HTTP 超时、连接池连接超时和本地稳定性冒烟脚本。
- 本地测试栈已完成数据库停止/恢复演练；恢复后连接池能够重新建立连接。100 次请求、20 并发验证通过，5xx=0、超时=0。

## 发布前剩余门禁

1. 完成数据库不可用时的结构化 503/缓存降级回归，确认不会出现“接口记录为 200 但请求实际超时”。
2. 注入飞书 HTTP 超时、同步队列失败和通知重试场景，确认退避、幂等、死信和恢复行为。
3. 核对生产 MySQL `max_connections`、主/后台池总上限、容器副本数和其他客户端连接，保留计算结果。
4. 回归项目、子任务、项目详情、文件上传/预览、归档恢复、飞书同步和通知；额外验证 100MB 以上 RAR 及 200MB 边界。
5. 生产发布后观察至少一个完整业务高峰窗口：5xx、连接池等待/超时、慢事务、OOM、同步失败和通知死信均无异常增长。
