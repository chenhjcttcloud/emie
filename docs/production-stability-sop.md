# 生产稳定性 SOP

## 目标

让故障可发现、影响可隔离、数据可恢复、发布可回滚。任何“稳定”结论都必须有指标、测试和回滚证据。

## 发布门禁

发布前必须满足：

1. 工作区无未确认改动，提交 SHA 与发布 SHA 一致。
2. Java 21 构建、全部自动化测试、前端语法检查通过。
3. 数据库备份成功且可读取，迁移脚本已审核。
4. 主/后台连接池配置、数据库最大连接数和文件目录空间已核对。
5. 项目、子任务、文件上传、飞书同步、通知重试关键链路回归通过。
6. 候选容器启动、健康检查、版本检查和双连接池检查通过。
7. 发布失败自动保留旧容器和备份，并执行回滚。

## 运行门禁

持续观察：

- 连接池 active、idle、waiting、timeout、leak；
- 接口 4xx/5xx、P95/P99、慢事务；
- JVM 堆、GC、线程和 OOM；
- 上传、缩略图、预览和存储空间；
- 飞书同步队列 pending/processing/fail 和最近失败；
- 通知 outbox、重试和死信数量。

## 资源生命周期规则

- 数据库连接只在短事务内使用，事务结束立即归还池；
- 数据库事务不得包住 HTTP、SFTP、压缩、图片处理或大文件读写；
- 文件流、压缩流、SFTP Session/Channel 使用自动关闭；
- 外部 HTTP 必须设置连接超时、请求超时和有限重试；
- 队列必须有幂等键、锁、退避、最大重试和死信；
- SSE、线程池和定时任务必须有超时、退避和关闭策略。

## 故障处理

先保护业务：停止重复重试和高耗时任务，保留现场日志和指标；再定位根因；修复必须先本地验证，生产只通过原子发布脚本执行。任何数据库或文件删除操作都必须先备份并提供回滚路径。
