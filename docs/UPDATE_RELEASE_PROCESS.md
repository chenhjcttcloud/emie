# EMIE 系统更新与发布规范

本规范适用于所有代码、页面、配置、数据库迁移和通知功能更新。任何更新必须按本流程执行，不允许只替换文件或只重启容器。

## 一、环境边界

- **本地测试环境**：用于开发和验收，默认地址 `http://127.0.0.1:8080`，局域网访问地址以当前部署配置为准。
- **代码仓库**：只提交经过本地测试的版本。
- **生产环境**：只有用户确认测试通过后才发布。

本地修改、仓库推送、生产发布是三个独立阶段，未经确认不得跳过测试直接发布生产。

## 二、本地更新标准流程

每次代码修改完成后，必须执行：

1. 检查工作区变更范围，确认没有混入无关文件。
2. 递增静态资源版本号。
3. 递增系统版本号 `system.version`，确保用户能收到系统更新提示。
4. 执行前端 JavaScript 语法检查。
5. 执行 Java 21 构建和自动化测试。
6. 重建并重启本地测试容器。
7. 检查应用、MySQL、Redis 容器健康状态。
8. 检查首页、核心静态资源和版本检测接口。
9. 确认版本检测接口返回新版本号。
10. 向测试人员交付后，用户首次打开旧页面必须看到“系统已更新”提示。
11. 用户点击“清理缓存并刷新”后，才开始功能验收。

标准脚本：

```bash
./scripts/test-update.sh
```

脚本成功必须输出 `test_update=ok`。浏览器冒烟检查即使超时，也必须以静态资源、容器健康和接口检查全部通过为前提，并明确告知用户。

## 三、测试验收要求

功能验收至少覆盖：

- 登录、角色切换和权限边界；
- 项目、子任务创建和详情查看；
- 图片、参考图、附件上传和预览；
- 通知触发、通知记录、失败重试；
- 日期选择、弹窗关闭和分页；
- 受影响页面的首次加载和刷新恢复。

发现问题时，回到本地更新流程，不得直接修改生产。

## 四、仓库推送流程

测试通过后：

1. 提交清晰的 Git commit。
2. 推送当前业务分支。
3. 核对远程分支提交号与本地提交号一致。
4. 向用户报告提交号，等待生产发布确认。

## 五、生产发布流程

用户明确确认后才执行：

1. 核对生产当前版本和目标提交号。
2. 执行完整 Java 21 构建和自动化测试。
3. 上传发布产物。
4. 备份生产数据库和当前容器版本。
5. 启动候选容器并执行健康检查。
6. 原子切换到新容器。
7. 检查生产首页、关键接口和公开访问地址。
8. 确认生产版本号已更新。
9. 确认旧版本备份和回滚信息完整。

标准脚本：

```bash
./scripts/publish.sh --all
```

只有同时满足以下条件，才可报告生产发布完成：

- `release_status=success`；
- 目标提交号与仓库一致；
- `public_http=200`；
- 数据库备份成功；
- 新容器健康运行。

## 六、系统更新通知规则

- 每次正式更新必须递增 `system.version`。
- 用户打开系统时，前端无缓存请求版本检测接口。
- 检测到版本变化后显示“系统已更新”弹窗。
- 用户点击后清理可控缓存、注销 Service Worker 并重新加载。
- 不清理登录令牌和已保存业务数据。
- 更新通知失败不得阻断正常登录和业务操作。

## 七、回滚规则

如出现无法登录、403/500、核心页面空白、数据写入异常或通知大面积失败：

1. 立即停止继续发布。
2. 保留现场日志和错误时间点。
3. 使用本次发布生成的数据库备份和旧容器版本回滚。
4. 回滚后重新执行首页、登录和核心流程检查。
5. 修复问题后重新走本规范，不允许在生产临时手改。

## 八、交付记录

每次更新必须记录：

- 更新内容；
- 本地测试结果；
- 仓库提交号；
- 生产发布号；
- 数据库备份位置；
- 健康检查结果；
- 是否触发系统更新通知；
- 如失败，记录失败阶段和回滚结果。

## 九、项目飞书群功能规划

### 9.1 自动创建项目群

产品企划创建项目成功后，由飞书应用自动创建项目群，群名规则为：

- 渠道定制项目：`定制-#项目编号-销售姓名（销售）`
- 公司常规品：`常规-#项目编号-产品企划姓名（产品企划）`

项目编号使用系统页面显示的编号，例如 `#102`，不使用合同编号或 EMIE 编码。

### 9.2 自动维护群成员

项目创建时加入项目关联的销售或产品企划。产品企划后续创建子任务并指定负责人时，自动将负责人加入项目群。所有与项目或子任务关联的角色均适用，包括：

- 销售
- 产品企划
- 设计师
- 供应链
- 产品推广

后续新增或更换子任务负责人时自动补充新成员；已经在群内的成员不得重复邀请。

### 9.3 项目群解散

项目处于“已完成”或“已终止”状态时，项目详情显示“解散项目群”按钮；项目未结束时不显示。

- 渠道定制项目：对应销售负责人可操作；
- 公司常规品：对应产品企划负责人可操作；
- 管理员可作为兜底操作人；
- 解散前必须二次确认；
- 解散成功后记录操作人、时间、项目编号和飞书群 ID；
- 已解散项目显示“项目群已解散”，不可重复操作。

### 9.4 飞书前置权限

该功能依赖飞书自建应用和机器人能力，需在飞书开放平台申请并通过以下权限：

- 创建和更新群组：`im:chat`
- 添加、移除群成员：`im:chat.members`
- 解散群：`im:chat:delete`
- 以群主身份管理应用创建的群：`im:chat:operate_as_owner`

应用必须负责创建项目群，并保存群 `chat_id`。解散权限受飞书群主和租户限制，权限未通过前系统只能保存待执行状态，不能假装解散成功。
