# 数据库双连接池迁移方案

## 目标

核心业务（项目、子任务、交付、驳回、验收、评分）与后台任务（飞书同步、通知重试、催办、归档、监控）使用独立连接池。后台异常或连接耗尽不得影响核心业务。

## 迁移原则

1. 主数据源保持现有 JPA Repository，不改业务行为。
2. 后台数据源使用独立 EntityManager、事务管理器和 Repository 包。
3. 后台 Repository 只允许访问后台任务所需实体，禁止被控制器直接注入。
4. 任何后台网络调用都必须发生在数据库事务之外。
5. 后台连接池默认 5 个连接，迁移完成并通过测试后才开启开关。

## 迁移顺序

1. 基础设施：后台 Hikari 数据源、EntityManager、事务管理器。
2. 通知链路：通知事件、投递记录、审计记录、失败重试、催办。
3. 飞书链路：同步队列和对账任务。
4. 归档与监控：文件归档、运行时连接池监控。
5. 测试环境压测：核心业务并发 + 后台任务持续运行，验证主池不受影响。
6. 生产发布：开关、连接数、回滚点和健康检查全部确认后再启用。
