# 权限系统发布与回滚清单

## 发布前

1. 冻结权限配置变更，记录当前应用提交和数据库版本。
2. 对生产数据库执行完整备份并通过 `gzip -t` 校验。
3. 在备份副本或同版本临时库连续执行两次
   `db/migrations/2026-07-24-add-permission-foundation.sql`，确认迁移幂等。
4. 核验权限定义 71 项、六类系统角色版本存在、读取权限均配置数据范围。
5. 执行 Java 全量测试、全部前端 JavaScript 语法检查和 `git diff --check`。
6. 使用管理员、销售、产品企划、产品推广、设计师和供应链测试账号完成权限验收矩阵。

## 发布顺序

1. 进入维护窗口，停止会产生角色或权限变更的后台操作。
2. 再次备份生产数据库。
3. 先执行权限底座迁移并核验表、外键、授权数量和范围数量。
4. 再部署应用，避免 Hibernate `ddl-auto=validate` 因缺表启动失败。
5. 检查首页、登录、`/api/auth/permissions`、项目分页、项目详情及管理后台。
6. 观察应用错误、403 数量、数据库连接和飞书同步队列至少 15 分钟。

## 权限验收

- 无页面权限时菜单隐藏，直接请求业务接口返回 403。
- 项目列表、数量、详情和写操作的数据范围一致。
- 直接构造其他用户项目 ID 无法读取或修改。
- 子任务交付、审核和评分必须同时满足功能权限、数据归属和业务状态。
- 自定义管理角色只能进入已授权的系统管理功能。
- 权限修改后版本递增，重新加载能力清单即可生效。
- 权限模拟器能解释功能权限、数据范围和最终结果。
- 历史版本回滚会生成新的审计记录，不能删除原历史。

## 应用回滚

1. 先停止新版本应用。
2. 恢复上一版镜像或提交并启动。
3. 本次权限迁移只新增表和数据，旧版应用不读取这些表，常规应用回滚无需删除权限表。
4. 不执行反向删除迁移；如数据库数据异常，使用发布前备份恢复到独立库核对后再决定。
5. 验证旧版登录、项目列表、详情和关键写操作。

## 权限配置误操作回滚

1. 在角色管理的“最近权限变更”中确认目标角色、操作者、时间和原因。
2. 使用权限模拟器验证目标历史版本的预期影响。
3. 填写回滚原因并执行版本回滚。
4. 确认角色权限版本递增、审计日志新增 `role.rollback`，相关用户刷新后恢复。
