# 数据库迁移执行规范

生产环境使用 `ddl-auto=validate`，迁移必须先备份，再执行，再验证结构。

## 幂等要求

已经执行过的历史 SQL 不直接改写。新增迁移必须满足以下之一：

- 通过 `information_schema` 检查字段或索引是否存在，再使用动态 SQL 执行变更；
- 或先写入迁移版本表，再以版本号保证只执行一次。

`CREATE INDEX`、`ALTER TABLE ADD COLUMN` 不允许裸执行，避免重复发布或迁移中断后无法重试。

## 后续治理

在迁移数量继续增长前，引入 Flyway/Liquibase 或轻量 `schema_migrations` 表，记录文件名、校验和、执行时间和执行结果；应用启动只校验已登记版本，不在启动阶段隐式修改生产结构。

当前已新增 `schema_migrations` 基础表。历史迁移不自动回填，避免伪造执行记录；后续发布脚本应在备份后按文件校验和登记新迁移，重复版本或校验和变化必须直接中止。
